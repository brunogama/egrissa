# ADR 0024: MASQUE uses typed UDP and IP data planes

**Status:** Accepted

## Context

CONNECT-UDP and CONNECT-IP use HTTP Extended CONNECT, but they do not provide a byte stream. A stream tunnel can split or combine writes. That breaks UDP datagram and IP packet boundaries.

The route planner already represents application intent as `Transport::Udp` or `Transport::Ip`. `RouteTopology::HttpConnect` identifies the proxy endpoint without making protocol mechanics part of the request or identity model.

## Decision

`transport-core` exposes separate `DatagramTunnel` and `PacketTunnel` contracts. `DataPlaneTransport` returns a `DataPlaneTunnel` variant together with adapter-specific typed negotiation state.

`masque-adapter` maps a UDP plan to CONNECT-UDP and an IP plan to CONNECT-IP. It constructs the required Extended CONNECT request fields at the adapter boundary. The connector receives the method, protocol, authority, scheme, path, and Capsule-Protocol setting as typed data.

The adapter tries HTTP/3 first. It tries HTTP/2 only after a classified pre-request HTTP/3 failure and only when the same service has an explicit HTTP/2 fallback advertisement. Request rejection and credential failure end the attempt. They never trigger an HTTP/2 or direct fallback.

## Consequences

The domain model retains `Tcp`, `Udp`, and `Ip`. MASQUE, HTTP versions, proxy authorities, URI templates, and credentials remain in the adapter crate.

The planner accepts UDP or IP for an `HttpConnect` route only when the endpoint advertises the matching CONNECT capability and an explicit HTTP/2 or HTTP/3 capability. Missing capabilities produce no eligible plan.

## Testing

Run `cargo test -p masque-adapter --test contract` for request construction, datagram and packet boundary preservation, negotiated fallback, and fail-closed behavior. Run `cargo test -p route-core --test topologies` for capability-gated planning.
