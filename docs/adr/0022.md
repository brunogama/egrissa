# ADR 0022: HTTP CONNECT adapter
**Status:** Accepted

## Context
M3 requires a real HTTP CONNECT adapter with optional TLS to the proxy. Proxy credentials, addresses, HTTP response details, and TLS mechanics must remain outside domain objects.

## Decision
Add an adapter-owned `HttpConnectAdapter` that implements `TunnelTransport`. It resolves opaque identifiers at the adapter boundary, supports optional Basic proxy authentication, and optionally uses Rustls to validate the proxy against system roots augmented by caller-provided DER roots.

## Consequences
The adapter emits only typed `TransportFailure` values and never exposes raw responses or credentials. TLS dependencies remain in the adapter crate. Runtime ownership of workload-facing tunnels remains separate from control-plane route establishment.

## Testing
Use local HTTP CONNECT interoperability fixtures for tunnel traffic, authentication rejection, and malformed/non-success responses. TLS roots are supplied explicitly in TLS fixture tests.
