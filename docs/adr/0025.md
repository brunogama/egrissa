# ADR 0025: Provider bindings project evidence into planner facts

**Status:** Accepted

## Context

Providers publish capabilities, binding validity, and credential references. Their availability can change over time. Mutable provider status would make planning depend on hidden adapter state and would weaken deterministic tests.

---
## Decision

`provider-core` models a provider binding as typed immutable data. A binding lifecycle states whether the binding is active or retired. An active lifecycle has an optional validity bound.

Availability and cooldown are immutable observations. `BindingAvailability::project` combines supplied observations and a supplied clock into a typed planner input. A cooldown wins until its expiry. An active binding materializes as a generic `UpstreamBinding` and uses only an opaque `CredentialRef`.

The reference adapter accepts configuration and observations. It publishes a standard `InventorySnapshot` for `route-core`. The planner continues to match generic capabilities without provider-specific branches.

Provider capability claims do not verify an egress path. `verification-core` remains the only source of verified egress properties.

---
## Consequences

Provider adapters own configuration, provider protocols, and secret resolution. Domain crates receive generic facts and opaque references. Callers supply observations and time for every projection.

---
## Testing

Run `cargo test -p provider-core --test binding` for lifecycle, observation projection, and ordering properties. Run `cargo test -p reference-provider-adapter --test contract` for configurable inventory publication and planner integration.
