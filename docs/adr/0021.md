# ADR 0021: Adapter-owned data-plane tunnels
**Status:** Accepted

## Context
`Transport::establish` reports control-plane establishment only. A real SOCKS5 TCP CONNECT adapter must retain the established stream so it can carry traffic; otherwise a successful handshake is merely a reachability probe and must not be presented as a usable tunnel.

## Decision
Add the transport-neutral `Tunnel` and `TunnelTransport` contracts to `transport-core`. A successful `TunnelTransport::establish_tunnel` yields an adapter-owned tunnel with asynchronous read, write, and close operations. The contracts use only `std` futures and I/O result types, so `transport-core` remains independent of Tokio and concrete transport implementations.

The SOCKS5 adapter resolves opaque endpoint, destination, and credential references at its own boundary. It owns raw credentials and concrete socket addresses; neither enters a domain object or event.

`Transport` remains the M1 control-plane establishment contract. The M2 adapter implements `TunnelTransport` directly rather than reporting a tunnel it cannot hand to the current runtime. Workload-facing runtime/session integration is a later concern.

## Drivers
Usable real adapter behavior, credential isolation, transport neutrality, and preservation of the desired/allocated/established/observed/verified state boundaries.

## Alternatives
Keeping a handshake-only adapter was rejected because it drops a successful tunnel and would overstate what it establishes. Adding Tokio I/O types to `transport-core` was rejected because it violates domain dependency discipline.

## Consequences
Adapters that carry traffic implement `TunnelTransport`; control-plane-only transports remain valid `Transport` implementations. The M2 SOCKS5 contract tests prove authenticated CONNECT and bidirectional tunnel I/O through a local fixture.

## Constraint
A tunnel is not verification, proof of identity continuity, or permission for direct fallback. Adapter failures remain typed and fail closed.

## Testing
Use a local SOCKS5 fixture to assert method negotiation, username/password authentication, CONNECT framing, bidirectional tunnel I/O, and missing-credential rejection.

## Revisit
When the runtime exposes workload-facing session ownership or supports multiplexed tunnels.
